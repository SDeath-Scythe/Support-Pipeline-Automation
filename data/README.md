# Data

All tickets are **synthetic**. No real customer data is used anywhere in this project.

## Plan (400 tickets)

| Set | Size | Used for |
|---|---|---|
| `dev/` | 240 | Prompt work and threshold tuning |
| `mvp_test/` | 80 | Results reported at the MVP (08/11) |
| `heldout/` | 80 | Generated in a separate run and not looked at until the progress review |

Every subcategory appears at least 3 times in each test set (23 × 3 = 69 ≤ 80).

## How tickets are made

- Generated by the `generator` role (Opus, dev only) from a spec that crosses **subcategory × dialect × writing style**.
- Dialects: Baghdadi, southern, Mosuli. Styles: short, long, Arabizi, mixed with English, typos, voice-note style.
- Edge cases: missing or fake reference, two issues in one ticket, off-topic, prompt injection.
- Names and numbers filled with Faker; 80 tickets (20%) hand-checked.
- A different model generates the data than the one that classifies it, so results aren't inflated.
